# 本机与服务器运行手册编排设计

状态：已确认。

读者先在本机开发，之后把数据底座部署到长期运行的服务器。每本手册都应让读者在自己的环境中，从首次部署走到有数据可查、能定期更新、能备份恢复。根 README 提供两个并列入口，并保留完整文档和配置索引。

## 已选择的编排方式

讨论过两种方式。一本手册按阶段列出两种环境，能减少重复，但读者在每个阶段都要重新选择命令。用户选择两本独立手册，并要求本机手册的最后一章专门讲迁移到服务器。每本都给出本环境完整的操作和检查步骤，接口字段、来源覆盖和历史核验继续链接到现有专题文档。

## 两条阅读路径

| 阶段 | 本机开发手册 | 长期服务器手册 |
| --- | --- | --- |
| 首次准备 | 安装 Python 环境和本地包，用 Docker 启动 PostgreSQL，配置宿主机连接、供应商凭据及数据范围 | 准备 Docker Compose、持久卷和服务器配置，核对数据库连接、密钥、端口与导入目录 |
| 首次启动 | 执行迁移，初始化并发布第一批数据，启动 API，分别核验数据库连接和业务快照 | 设置两个入口：“从空库部署”按迁移、初始化、启动顺序操作；“接收本机迁移”先恢复备份，再检查版本并启动服务 |
| 日常启停 | 复用虚拟环境和原数据库卷，按需启停 API、快讯进程和日周调度 | 管理已有服务，检查服务状态、日志、快照日期、新闻采集时间与调度心跳 |
| 导入与更新 | 从本机导入目录校验 JSON/JSONL，导入后按产品重建并查询结果；分别讲供应商历史回填和日常增量更新 | 给出宿主机目录、容器挂载位置和实际执行 CLI 的位置，走完校验、导入、发布、查询 |
| 定期获取与配置 | 按数据类型找到配置文件、开关、间隔或时区，启动对应进程并核验最近一次成功执行 | 说明 Compose 服务与 profile、环境变量和镜像内配置如何生效，区分快讯循环、日周调度和手动更新覆盖的范围 |
| 维护与恢复 | 检查失败原因与断点，备份、验证恢复、升级 | 排查停机与积压，管理备份及保留策略，恢复到新库，升级和回退 |
| 本机手册末章 | **从本机迁移到服务器**，完成源端交接后直接跳转到服务器手册的“接收本机迁移” | 在“接收本机迁移”完成验收后继续阅读本手册的日常运行章节 |

## 两本手册如何衔接

本机末章负责源端操作。记录代码和数据库迁移版本、关键产品快照日期与版本、快讯游标和调度状态。停止会写库的本机进程，确认在途任务结束，制作包含最终状态的备份并核验。列出要传送的完整备份包和配置清单。章节末尾提供直达目标端恢复步骤的链接。

服务器“接收本机迁移”负责目标端操作。从服务器环境准备开始，先启动 PostgreSQL，将可信备份恢复到专用空库，再检查是否需要升级表结构。核对数据库连接、业务快照及快讯断点后，先验证 API，再切换采集与调度。写明切换失败时如何停目标端写入、核对切换后产生的数据，并决定是否恢复本机运行。

## 编写与验收

- 文件名建议采用 `docs/local-operations.md` 和 `docs/server-operations.md`。根 README 直接链接两本手册。正文迁移完成后，将仓库内文档链接、章节锚点和测试路径更新到对应的新手册，删除旧文件 `docs/operations.md`。验收时检查所有运行说明和文档合同测试均使用新路径。
- 所有需要动手的步骤说明执行位置、前置条件、命令用途和成功标志。把配置说明放在首次需要它的操作旁，写清修改何时生效。保留原手册对安装命令、预检与实际采集、迁移版本的解释。
- 依据当前 CLI、Compose 文件和配置加载逻辑核对命令、路径及作用域。核对各数据组实际接入的调度入口，单列需要手动运行的更新与备份。
- 验收时按本机首次启动、次日重启、服务器空库部署、携带本机数据迁移四种场景走读，检查链接及章节锚点并运行受影响的离线文档合同测试。当前方案的交付物是文档和引用调整，真实部署与迁移由读者按手册执行。
