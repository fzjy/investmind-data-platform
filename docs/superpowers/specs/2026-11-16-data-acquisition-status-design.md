# 按对象与数据条目维护获取状态

设计状态：待用户确认。本文记录已经讨论的规则及建议的实现边界，尚未授权实施产品代码或数据库迁移。

## 目的和已经确认的要求

管理台与 InvestMind 等消费项目需要回答：指定对象的指定数据是否可用，以及最近一次实际获取或检查是否成功。判定不推测官方是否已经发布新一期，不根据数据日期计算过期。

- 股票按“证券 × 数据条目或指标”独立维护。例如 `600519.SH` 日行情成功、分红失败，两个状态互不覆盖。
- 宏观按指标独立维护，基础系列、派生系列及专题子系列有各自身份。
- 三类审计结果为正常、数据获取失败、数据缺失；暂停、运行中、无可信执行记录、计算不适用单独说明，不强行归入三类。
- 数据缺失优先：没有可用数据且采集失败，显示缺失，同时保留失败原因。
- 记录类数据正常查询并证明结果为空时，可以成功。数值 `0` 有效，`NaN`、无穷大不作为有效数值。
- 保留历史数据、最近尝试时间、最近成功时间、错误原因和运行关联。
- 用户已选择统一状态表方案；消费项目可以读取状态进行审计。
- 宏观保持既有 `collectionAudit` 合同兼容，管理台沿用 InvestMind 的分类顺序。

## 现状与依据

当前采集凭证分散在 `ops.job_run`、`ops.job_failure`、`ops.job_cursor`、`raw.ingestion_batch`、原响应和 `ops.macro_series_state`。股票请求有证券、数据集、窗口、分页及缓存来源；不能将整个股票池的一次成功扩散给所有证券或数据集。

`backend/app/macro/audit.py` 和 `audit_records.py` 已只读整理基础系列、扩展、官方文件和企业财报凭证。`GET /api/v1/macro/insights` 及旧兼容路径在响应顶层附带 `collectionAudit`，每次读取当前执行证据，业务 `data` 和 `meta` 仍为已发布快照。审计读取失败时返回 `collectionAudit: null`，不破坏业务响应。

InvestMind 的 `src/modules/macro/audit/collection.ts` 严格校验该合同，接受 `success / failed / unrecorded / running / paused`，不能直接替换成三类审计结果。`rules.ts` 再结合实际页面值分类，`build-report.ts` 核对基础值的数据期和实际来源，企业、派生分析另外检查适用范围和依赖。

依据代码位于本仓上述模块、`backend/app/stocks/update/repository.py`、`backend/tests/macro/test_collection_audit.py`，以及相邻网站仓的 `src/modules/macro/audit/`。网站代码仅作为兼容依据读取，本轮修改范围为数据底座。

## 方案比较与选择

| 方案 | 取舍 | 决定 |
| --- | --- | --- |
| 查询时遍历既有凭证并临时汇总 | 不新增状态表，但采集器差异、查询成本和合同一致性难维护 | 已讨论的备选 |
| 统一状态表，保留原始凭证与兼容适配 | 新增迁移并接入采集流程，换取稳定的状态身份、统一查询和可追查依据 | 用户选择 |

下列具体表名、接口路径、分页上限与分类器归属为本设计的建议，需随本文确认。实施者可调整文件划分和索引细节，不能自行改变身份、分类语义或既有返回合同。

## 身份和覆盖范围

使用现有 `docs/data-catalog.json` 与主题条目的稳定 ID 建立状态绑定清单。清单逐项声明对象粒度、来源适配器、可用性规则、依赖和执行入口；静态文档条目不能仅因存在便被认为已有成功记录。

状态身份包含 `entry_id`（目录条目）、`item_id`（条目内可独立审计的指标，为空表示整个条目）、`subject_kind`、`subject_key` 和 `scope_kind`。同名字段按所属条目区分。

| 内容 | 对象及状态粒度 |
| --- | --- |
| 股票日行情、财报、分红、公告等 | 证券代码 × 目录条目；不会将某只股票的所有内容合成一个状态 |
| 合并在一个目录中的独立指标 | 使用独立 `item_id`，例如三种股息率分别读取各自结果及依赖；原始报表按报表条目记录执行，按字段检查可用性 |
| 基础宏观、扩展子系列 | 系列 ID；一项专题中的新房/二手房、不同交易所等已独立定义的系列不混为一个状态 |
| 指数、ETF、期货、外汇 | 配置中的规范品种代码 × 数据条目，不仅按整个市场任务汇总 |
| 行业、地域、市场聚合、企业统计、公共输入包 | 已发布产品及明确的对象范围，结果按依赖和实际可用内容评估 |
| 新闻、外部文件 | 实际来源及内容类型；文件导入另外保留文件/批次身份，成功导入不证明来源真实性 |
| 历史兼容或尚未供给的登记内容 | 有凭证时展示对应范围；没有可信记录时单独说明，实际必要值缺失仍可判缺失 |

当前目录全部条目都必须有绑定或明确的未供给/历史留存说明；不能只实现股票日行情和基础 CPI。目录中字段不因此逐列新增状态数据库列。

`scope_kind` 区分日常获取/检查与历史补采。每次结果还带冻结的证券、日期/报告期窗口、来源、合同版本和计划身份。历史补采成功不会覆盖日常检查失败；修复同一日常失败范围可以更新该范围的结果。历史接口已发布数据可与当前采集状态一同读取，时间含义必须分别说明。

## 两层状态及判定规则

### 采集证据

新增 `ops.data_acquisition_state`，作为各采集器持久凭证的统一摘要。原始作业、失败、游标、原件继续保存，不把状态表当作完整运行历史。

建议记录身份、最近尝试及其计划/窗口、执行结果、最近成功时间及其范围、当前尝试标识、实际渠道、原件/批次/作业引用、计数、错误码和脱敏原因。状态读取的 `readAt` 与原始执行时间分别提供。

源执行状态沿用 `success / failed / unrecorded`，另有当前执行中和暂停信息，对外投影可形成既有五种状态，保留暂停前的成功/失败证据。来源启用、定时入口启用和进程运行分别表达；某个定时入口停用不抹去人工执行的事实，也不自动宣告来源已暂停。旧 `collectionAudit.enabled` 继续遵循其现有来源配置语义，新查询接口可另外提供受管任务启停信息，不能改变旧接口的暂停分类。

- 有效请求/检查完成、必要分页/文件槽完成、校验及相应持久化成功，才能形成成功凭证；HTTP 200、首页有行、作业总状态、仅有一条历史业务数据均不足以证明成功。
- 请求、解析、校验、持久化发生真实错误，记录失败，并保留仍可用的旧数据。
- 跳过、未到执行时间、达到预算但没有实际执行、缺少凭证、未完成计划与无法确认的中断不伪造成功或供应商失败；保留 `unrecorded` 及原因。
- 明确的分页、校验或持久化错误属于失败；只是计划尚未完成则单独说明，不能把已有的确定错误降成未知。
- 同一条目的必要子请求有失败时，该次执行为失败并报告部分完成数量。仅成功重试同一个失败范围后才能解除该项错误；其他股票或其他窗口的成功不能清除它。
- 读取已保存原件并完成真实验证可以形成“本地检查成功”，标明使用缓存及原件时间，不能冒充供应商新请求。仅因沿用上一次状态而没有执行检查，保留原时间。
- 采集正常完成但没取得本次目标的新记录时，执行可以成功；是否缺数据由可用性规则判断，不按推测的最新日期判失败。

### 审计结果

统一分类器结合采集证据和指定数据视图，按以下顺序评估。

1. 当前范围已暂停或仍在执行，单独说明，旧数据可查看。
2. 必要值无效或缺失，判 `missing`；采集同时失败时原因中保留错误。
3. 有可用数据且相关最近执行失败，判 `failed`，保留旧值。
4. 有可用数据且有可信成功凭证，判 `normal`。
5. 有数据但没有可信执行证据，单独说明，不能默认正常。

接口层以 `normal / failed / missing / excluded` 表达，`excluded` 是“单独说明”，不计入三类汇总。展示名称沿用 InvestMind：正常、数据获取失败、数据缺失。

数值以有限数值为准，`0` 有效。事件集合需区分“有记录”“已完整检查且确认为空”“未查/未核全而为空”，前两种可用，最后一种不作为成功的空结果。证券不存在、不在来源覆盖范围或计算不适用时单独说明。

计算结果无效先判缺失；有结果但必要依赖失败判失败；有结果但必要依赖缺失判缺失；必要依赖均正常且自身计算/发布证据适用才能判正常。零或负分母导致口径不适用，保留具体原因，不伪造成采集失败。

暂停、运行中与不适用的排除规则和单项/依赖合并优先级保持现有网站行为：普通项先判断暂停/运行中；派生及企业项以其现有组合规则为兼容基线。执行证据、业务值和发布范围不匹配时单独说明。

分类器负责通用规则和底座内容的可用性判定。消费项目自行选择的季度、行业或用户私有试算仍可在项目中进一步审计，不能把底座的某一范围结论当成所有页面范围均正常。

## 写入、并发和恢复

各采集入口通过公共状态写入服务登记与完成，不在管理台浏览或公共 GET 中修改状态。新表与完成凭证在合适的提交边界一起提交；事务失败不得提前发布成功。原有流水线分多事务保留的已入库结果和检查点继续可恢复，终态要反映实际完成情况。

日常获取由现有任务/采集锁保护；另外使用尝试身份和条件更新，较早开始、较晚返回的旧尝试不能覆盖后来尝试的状态。相同尝试重入幂等；成功时间只能来自可信成功事件，失败不能清空最近成功信息。

批量响应按已证明的请求范围拆到对象，未请求的股票不更新；分页或文件计划完整性沿用现有严格凭证判断。中断遗留的运行记录必须经恢复检查后标明“结果待确认”，不能长期据一行 `running` 宣称进程仍在运行。

配置暂停与运行中不覆盖上一次终态。状态库写入失败应作为本轮记账/持久化错误处理并留日志，不能继续宣称本轮状态保存成功。读取失败时明确返回不可用，不能使用旧的成功缓存掩盖；宏观兼容路径继续使用 `collectionAudit: null` 降级。

## 查询和兼容合同

### 现有宏观接口

`GET /api/v1/macro/insights` 和 `/api/data/macro-insights` 的业务 `data`、`meta`、查询参数和顶层 `collectionAudit` 位置不变。

`collectionAudit` 保持 `schemaVersion: 1.0`、`basis: current-collection-records`、`readAt`、`catalogVersion`、`entries`，单项仍是 `id / enabled / status / checkedAt / successAt / errorCode`。现有基础系列、官方专题、交易所、企业财报的 ID 和状态取值原样适配。不能将目录 ID 生硬替换既有审计 ID。

原有宏观状态整理器作为迁移期和历史凭证的适配来源；新表无可信覆盖时读取既有适配器结果，而不因“表已迁移”制造全站缺失。是否切到新表由该范围实际接入与可验证凭证决定。对未变更的证据，切换前后旧合同结果应一致；额外证据使结论改变时需有明确回归用例。

不修改 InvestMind 仓库，也不要求它立即接入新增接口。它继续将页面实际值与 `collectionAudit` 组合审计。新表不会直接改变旧返回字段的含义。宏观原有 `stale`、历史缺期及备用来源标志不改作采集失败判据。

### 新增统一查询能力

建议新增只读 `GET /api/v1/data-status`，按条目、对象类型/代码和范围过滤，使用稳定游标分页，默认 25 项，上限 100 项。参数精确名称和游标编码由计划确定，必须支持查询单只股票的多个条目、单条目的多只股票、宏观系列及有界批量对象，禁止无界返回全市场。

返回带版本的状态信封：`schemaVersion / readAt / items / nextCursor`。每项包含稳定身份、中文名、数据视图、执行证据、可用性、三类或单独说明的审计结果、原因及受限的运行/批次关联。

数据视图区分 `stored`（当前已入库数据，管理台默认）和 `published`（指定产品及发布版本内实际数据，消费项目按需选择）。发布视图必须携带有效产品及发布版本信息，不能用 Core 有值证明指定快照里有值；未支持的发布映射明确说明，不能退回 Core 判正常。未指定版本时可读取当前指针，响应仍写明实际版本。

该接口的执行证据为当前状态，不因查询历史发布版本变成历史执行证据。消费项目应核对数据视图、对象、条目和来源；凭证仅属于另一对象、来源或无关历史补采时，不能认作本项日常检查成功。数据日期较早、值的日期不等于最近请求窗口终点、或正在查看历史发布版本，本身都不构成失配；当前检查成功与历史有效值可以形成正常，沿用“不判断最新”的约定。若调用方明确审计某个历史窗口，需使用能绑定该窗口的证据，并在响应中说明其检查范围。

数据库或状态查询整体失败返回明确的 503；单项没有可对应证据返回单独说明。错误中不暴露连接串、Token、文件正文或私有持仓。

新接口遵循现有公共 API 的部署和访问配置。管理台通过受保护的本机路由调用同一只读服务，继续限定本机访问，不新增公网监听或独立前端服务。不向现有股票业务响应强行插入新字段；消费项目可按需采用新接口。

## 管理台与文档

在现有数据条目详情附加当前获取状态，按对象查看，股票和品种支持代码筛选及分页；宏观按系列显示。状态附加信息与静态文档分别读取，数据库异常仍能阅读文档。

显示三类结果或单独说明、实际数据/报告期或确认空结果、最近检查/成功、简短原因和查询范围；失败可沿现有入口查看运行关联。暂停、执行中和无可信记录应显示中文原因，不能只用一个绿色标识。

来源字段和数据表链接保持现有用途。任意业务表的一行不新增重复状态列，数据表页可以继续查看统一状态表。静态目录增加状态绑定和查询能力说明，不把当前状态写进版本控制下的文档 JSON。常规读取不触发采集、重算、回填或文件导入。

本轮不新增自动刷新机制或通知渠道，沿用管理台现有读取行为并显示状态读取时间；InvestMind 标签页缓存行为不在本轮更改范围。

## 历史初始化和部署影响

通过 Alembic 新增状态表及索引，不回写业务行情、财报、分红和已发布快照。迁移前盘点既有证据并生成只读初始化报告；初始化可重复执行，只能从能绑定到明确对象、条目、范围及终态的既有凭证恢复。不能凭已有业务值或整池任务成功补写单项成功。

无凭证的数据保留“已有数据、执行结果未确认”或必要数据缺失；旧质量原因不冒充真实获取失败。历史初始化不访问供应商、不自动补采、不重建业务产品。

上线在任务安全停止或完成当前轮次后执行迁移并更新 API/采集进程。需要一次常规进程重启，无需新增服务、数据库重建或全量重新采集；本轮设计阶段不执行这些操作。回滚代码时保留新增表和既有证据，不能以删表清空记录作为自动回滚。

## 验收

1. 同证券日行情成功与分红失败并存；不同证券、系列和专题子项互不覆盖，批量响应不扩散成功。
2. 有值成功、有值失败、无值失败、数值零值、非有限值、确认空事件、未核全空事件均按已确认规则分类；三类统计排除暂停/运行中/无可信记录/不适用。
3. 部分失败、分页未完成、缺文件槽、预算跳过、缓存检查、源权限错误、解析错误及落库失败保留真实含义，不以 HTTP 状态或顶层任务状态代替。
4. 历史补采不覆盖日常状态；同一失败范围恢复可解除错误；重复执行幂等、旧尝试晚完成、进程中断恢复均不产生虚假成功。
5. 初始无表/无凭证、已有旧凭证、重复初始化、状态库异常均不会制造正常结果或破坏已有业务数据。
6. 现有宏观响应在普通与旧兼容路径上通过严格合同回归；`data`、`meta`、旧审计 ID、时间和五种执行状态兼容，失败继续附 `null`。用相邻网站现有解析器及审计样例验证，网站仓保持只读。
7. 派生、企业及公共输入包按实际依赖和指定范围评估；当前 Core 与历史发布视图分开，有来源但值与元数据不符时不判正常。
8. 目录覆盖检查列出全部条目绑定、字段独立身份及尚未供给说明；状态接口有界查询，静态文档不依赖状态库，读取没有供应商请求或业务写入。
9. 迁移和集成测试使用隔离数据库；真实本机验收只读，任何真实迁移、重启或采集须在实施阶段确认运行条件，不能在设计验收时顺带触发。

## 留给实施者的常规决定

模块划分、ORM 字段长度、索引组合、分页编码、复用适配器的组织和测试夹具可在计划中决定。计划必须先输出逐目录绑定清单和采集入口清单，再按域接入，并说明每个接入范围如何保留旧宏观合同与原有检查点；不能通过仅新增空表和展示字段宣称全量完成。
