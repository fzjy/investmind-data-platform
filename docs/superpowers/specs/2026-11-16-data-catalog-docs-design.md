# 按数据内容组织的接口文档设计

用户已于 2026-11-16 确认设计。本文描述本机管理台“接口文档”的拟调整行为。

## 用途与已确认的方向

使用者从股票日行情、财务报表、分红、股息率、宏观系列等数据内容进入，了解含义、字段、来源、获取频率、存储位置、历史保存情况和调用方式。参考 [Tushare 数据接口文档](https://tushare.pro/document/2) 的分类目录及单项详情组织方式。

用户已选定结构化数据目录、统一生成文档页的方案，并确认交互示例。详情中的数据表名可点击，在新标签页打开现有管理台的对应表。是否保存历史等判断先给出“是”或“否”，然后说明范围；涉及的指标或字段同时展示英文标识和中文含义。

本轮交付包含文档目录与核对整理工作，继续沿用现有底座接口的查询能力。为每类数据标明独立查询接口支持情况、聚合接口返回位置和查表方式。真实接口按数据内容补充查询能力属于后续需求。

## 方案比较

| 方案 | 维护方式和取舍 | 选择 |
| --- | --- | --- |
| 结构化目录生成详情 | 每个数据内容维护统一元数据、字段与来源映射。接口入参读取当前 OpenAPI。表跳转、搜索及“是／否”展示统一处理，首次需核对整理内容 | 用户选择。适合来源、表、历史、公式等信息重复出现的本机数据底座 |
| 每类数据一篇 Markdown | 模板容易编写长文，链接、字段格式和接口参数由各篇分别维护 | 已讨论的另一种方式 |

## 页面与浏览

沿用管理台主导航的“接口文档”，在文档区内提供分类、搜索和详情。分组按数据内容命名。建议由实施者整理为股票数据、指数与 ETF、商品与汇率、宏观经济、财经内容、组合公共数据，具体名称随盘点调整。股票下可按基础资料、行情估值、财务报表、股东回报与派生指标等展开。

目录项有稳定标识和中文名。同一数据或指标只有一个主说明条目，各消费接口引用它。目录树相邻或多处关联不复制口径。利润表等同类数据可以含多个字段，语义、单位或频率不同的宏观系列保留独立可定位说明。标准与 VIP 上游端点若提供同一数据，作为不同获取方式说明。

目录搜索支持中文名称、英文标识、字段、来源名和表名。匹配字段可定位到所属条目并显示字段中文名。URL 保留选中条目，刷新和浏览器前后退可恢复。无匹配、未知条目、字段待核验都提供明确反馈。

详情依次为数据名称及含义、来源与频率等摘要、获取方式、参数、返回或存储字段、派生计算、历史说明及依据。已有 Swagger 与 OpenAPI 保留辅助入口。专题原文按需链接，常用信息直接出现在详情页。

### 数据表跳转

摘要和字段映射中的所有已登记表名都可点击。链接使用当前管理台的实际 origin，附加 `/admin/#tables?s=<schema>&t=<table>`。当前用户端口为 11383，正式实现从浏览器地址构造链接，兼容以后改端口。链接在新标签页打开，文档保留原阅读位置。

可用表目录用于标明该部署是否已建表。数据库离线时保留说明和链接，表浏览页反馈连接问题。若已确认目标表不存在，应标出“当前库暂无此表”。识别表名及字段路径使用结构化映射。例如 `core.income_statement.data.n_income_attr_p` 的链接目标是利润表 `core.income_statement`，字段说明标明 JSON 内的归母净利润位置。

## 目录范围与内容依据

覆盖仓库已接入的数据内容和底座已经实现的派生指标，整理时以当前代码、配置、输入输出合同及现有字段清单建立覆盖清单。已有十个 v1 公共接口都须能从相关条目查到实际用途和字段位置。历史兼容、默认停采、尚无原件或暂无来源的已登记数据保留真实状态。

建议盘点下列内容。

- 股票基础资料、交易日历、行业和成员、地域，股票日行情及复权因子、每日估值与股本。
- 利润表、资产负债表、现金流量表、财务指标、分红、股东与机构持仓、股东户数、公告、业绩预告与快报、主营分部等已接入主题。各主题注明常规采集、专题采集与历史兼容的区别。
- 指数与 ETF 资料、成分、日行情、份额、市场聚合，以及已接入的商品合约、行情和汇率。
- 基础宏观系列、扩展专题、官方目标与企业范围相关数据、底座已有的利差或比值等派生结果。
- 财经快讯、公开内容、文件导入数据，以及组合模块已提供的公共参考输入。
- 股票派生指标、股息率及估值指标、风险规则，以及上列主题中底座实际生成的派生值。

范围依据包含 `docs/tushare-field-consumers.md` 及机器回执、`docs/official-source-fields.md`、`docs/field-consumers.md`、各主题供给文档、`docs/derived-history.md`、宏观目录、股票指标注册表和 ORM 模型。实施计划先列出实际条目清单及依据，完成时逐项对照，避免只交付两个示例。页面试算中的用户参数结果说明计算归属和入口，底座没有保存的结果明确标记。

旧审计结果保留核验日期，不把当时的行数、最新日期和来源写成当前实况。本次整理通过只读文件及必要的数据库核对完成。未确认的字段或旧合同保留“待核验”和具体缺口，已有明确代码证据的内容给出确定结论。

### 每个条目的说明

| 说明 | 必需内容 |
| --- | --- |
| 名称与数据含义 | 中文名、稳定英文标识、覆盖证券或对象、时间维度和单位 |
| 数据来源 | 原始发布方、实际采集渠道或供应商接口，候选及备用来源单列。已核验实际来源须带版本或核验时间 |
| 获取频率 | 数据观测频率、上游发布节奏、底座采集与构建规则分别记录。运行配置能读取的日程标明配置来源及目标／生效状态 |
| 数据表 | 原件、归一化输入、派生结果与发布快照各表的中文用途及字段路径；用实际读写路径核验 |
| 历史保存 | 是否保留历期记录、是否保留同一业务日期的修订／每次重算、现有接口能否查询历史，分别回答 |
| 派生情况 | 逐字段回答是否派生；页面级摘要指出具体哪些字段发生转换或计算 |
| 调用能力 | 独立查询、聚合获取、查表三种能力分别说明。对于“同类独立接口”给出是／否和依据 |
| 核对依据 | 代码或合同、文档位置、核验日期及未决项。读者可按需展开 |

表结构证明可存哪些维度，已有数据和写入路径共同决定“已经保存”的说明。按日留存不代表每天都有数据，记录内容哈希不代表每次修订旧值都还在。

## 判断值、历史与字段格式

已确认的布尔说明以“是。”或“否。”开头，然后写条件和保存范围。若证据不足，明确写“待核验”，说明缺少的证据。结构上用 `true`、`false`、`null` 表达，避免把未知映射成否。

股息率条目的已确认示范口径为以下三项。

1. **保存指标历史为是。** 已计算并落库的结果在 `derived.metric_value`，按 `ts_code`（证券代码）、`metric_id`（指标标识）、`as_of`（估值日）和 `formula_version`（公式版本）保存。实际覆盖日期以留存记录为准。
2. **保留同日同公式每次重算为否。** 上述四项相同，现有写入更新原结果及输入引用。不同估值日或公式版本各存记录。
3. **当前选股接口按历史日期查询为否。** 列表取已发布快照。指标已入库和当前接口可查询历史分别说明。

字段按用途展示英文名、中文含义、类型、单位、空值说明、来源、表字段和派生情况。英文名称相同而语义不同的字段按所属内容及完整路径区分。接口字段、上游字段和存储字段各自标明角色。例如返回的复权收盘价 `close` 与未复权存储值 `core.daily_price.close` 说明转换关系。

公式中的输入指标均配中文含义。派生说明包含公式、输入表列、单位换算、统计窗口、公告可见时点、修订选取、适用条件、缺失和冲突处理、公式版本及落库位置。同主题多种公式可切换查看，股息率的财年实派、本年预期、未来十二个月沿用示例的三项组织方式。每项都可以独立定位。

## 结构与维护

建议由实施者维护版本控制下的 `docs/data-catalog.json` 作为目录数据，必要的内容可按主题分文件。沿用 FastAPI 本机管理子应用提供只读目录响应，由前端统一渲染。文档内容修改随项目发布，无需增加数据库表或常驻前端服务。

结构包含以下实体，命名和文件划分交给实施者在计划中确定。

- 数据条目保存分类、中文名、英文 ID、范围、来源、频率、历史各判断项、字段和派生口径。
- 表映射保存 schema、表名、中文用途以及字段或 JSON 路径，前端据此生成真实链接。
- 获取方式保存接口 method、path、响应路径和参数中文解释，并声明独立或聚合。仅有数据库能力时显示查表入口。
- 每个判断项保存布尔值或未知、中文解释和依据。证据可引用代码路径、配置键或现有文档，包含核验时间和静态／运行值的属性。

入参约束以当前应用生成的 OpenAPI 为依据，解析路径、查询、请求头和请求体及引用模型的必填、类型、范围和默认值，目录补充中文解释及业务关系。部分响应使用无强类型的快照对象，其字段含义与 JSON 路径须核对实际生产提供方、构建器及合同，不能由 OpenAPI 空 schema 推断。

构造示例请求时使用当前 origin 和真实参数，注明返回片段是否为说明样例。文档页查询目录、OpenAPI 和现有管理信息，无需触发供应商采集。接口或表已变更但目录有旧引用时，校验明确报告断链位置，页面保留该条目并提示待更新。

日程复用管理台已有的已保存目标与工作进程回执。未启用任务显示“已关闭”和配置规则；规则依赖多个采集来源或构建步骤时，逐项说明。缺少运行证据时保留规则描述与待确认状态。目录可离线打开，数据库故障仅影响查表及需要实时查询的信息。

## 验收

1. 从分类和搜索分别找到股票日行情、财务报表、股息率与宏观数据；刷新、前后退后保留条目；多种聚合接口指向同一主说明。
2. 所有表名链接使用当前 origin，分别在 11383 和另一测试端口正确打开对应表。长 JSON 字段路径仍链接到正确表；文档标签保留阅读状态。
3. 股息率历史三项按上述是／否明确呈现；有证据不足的条目单独显示待核验。全部已展示字段和计算输入同时具备英文名与中文含义。
4. 日行情样例分别说明原始值与复权输出。股息率三个公式的窗口、输入、版本、单位和空值规则可阅读和定位。
5. 每个登记的公共接口可从目录找到参数与返回内容，必填和默认值与当前 OpenAPI 一致。响应路径、来源和表关系都有证据。
6. 逐项核对实施盘点清单，已接入内容都有条目或说明归属。旧审计观察带时间，当前配置值与运行中生效值有区别。
7. 模拟未知条目、旧路由、缺表、数据库离线与目录字段缺失，页面能反馈具体问题。文档元数据和单元格内容按文本渲染，继续受现有本机访问边界保护。
