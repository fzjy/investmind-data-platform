# 股票日频数据查询与首轮盘点

本页保留三个日频接口的合同和首轮实库对账。后续接入的事件、分红时点查询及其在 InvestMind 中的使用见[股票与组合合同](foundation-stock.md)，各域最终处置见[整体验收](foundation-acceptance.md)。

三个只读查询提供服务所连接数据库的当前 Core 库存。日期表示数据所属交易日。InvestMind 的工作台发布器读取同一范围的 Core 数据，计算复权图表和指标，再以产品版本发布。查历史交易日可以取得当前库里该日的值。公共工作台 GET 返回当前发布版本。核对往期保存的内容可在底座内调用 `SnapshotRepository.read_versioned(product, version)`，历史字段按产品留存规则解释。[快照读取器](../backend/app/shared/repository.py)

## 查询

| GET 路径 | 库存来源 | 每行的数值字段与单位 |
| --- | --- | --- |
| `/api/v1/datasets/stock-daily` | `core.daily_price` 类型化列 | `open`、`high`、`low`、`close` 为未复权价，`pre_close` 采用上游除权昨收口径，`change` 为涨跌额，均为元。`pct_chg` 为百分数，`vol` 为手，`amount` 为千元。 |
| `/api/v1/datasets/stock-adjustment` | `core.adjustment_factor.adj_factor` | `adj_factor` 为复权因子。查询按因子表自身的交易日返回。 |
| `/api/v1/datasets/stock-daily-basic` | `core.daily_basic` | `pe`、`pe_ttm`、`pb`、`ps`、`ps_ttm` 为倍数。`turnover_rate`、`dv_ratio`、`dv_ttm` 为百分数。`total_mv`、`circ_mv` 为万元，`total_share`、`float_share`、`free_share` 为万股。 |

每行还包含 `symbol` 和 `trade_date`。数值按库存的十进制精度输出为 JSON 数字。需要保留全部有效位的调用方可用十进制解析器读取响应。每日估值的 `pe_ttm`、`ps_ttm` 及三项股本来自同一行 `data` 中的登记字段。股息率采用供应商的定义，工作台的派息模型有独立的指标标识。[行情合同](https://tushare.pro/document/2?doc_id=27) · [复权因子合同](https://tushare.pro/document/2?doc_id=28) · [每日指标合同](https://tushare.pro/document/2?doc_id=32)

按单股区间同时给出完整代码和首尾日期，两个边界都包含。按单日查询给出 `trade_date`，可进一步限定一只股票。日期格式为 `YYYY-MM-DD`。

```http
GET /api/v1/datasets/stock-daily?symbol=600519.SH&start_date=2026-10-01&end_date=2026-10-21
GET /api/v1/datasets/stock-daily-basic?trade_date=2026-10-21&limit=20
GET /api/v1/datasets/stock-adjustment?symbol=000001.SZ&trade_date=2024-06-14
```

第三个请求在本轮本机盘点时的结果如下。

```json
{
  "data": [
    {"symbol": "000001.SZ", "trade_date": "2024-06-14", "adj_factor": 125.05}
  ],
  "meta": {
    "dataset": "stock-adjustment",
    "coverage_scope": "stored",
    "next_cursor": null
  }
}
```

结果按交易日、证券代码升序返回。每页默认 500 行，可设置为 1 至 2,000。下一页沿用相同数据集和筛选范围，并传入上一页的 `meta.next_cursor`。`null` 游标表示已读完。每次请求读取当时已提交的数据，跨页期间发生的补采或修订可能影响后续页。非法参数和失配游标返回 HTTP 400，数据库不可用返回 HTTP 503。

`coverage_scope=stored` 表示所查范围内的本地库存。空数组表示查无记录，已有行的缺值返回 `null`，有效零值返回数值 0。需要判别是否采全时，可按数据条目与证券查询采集凭证。[获取状态查询](platform-api.md#数据获取状态)

## 2026-11-18 本机盘点

盘点在 PostgreSQL 只读事务中完成。行情、复权因子和每日估值均涉及 50 只股票，日期从 2023-08-21 到 2026-10-21。下表中的“额外捕获”按相同来源、接口、请求哈希和正文哈希分组，统计每组首条以外的记录。判断一次请求能否省掉，还要对上它当时的范围、字段、完整性和修订检查要求。

| 数据集 | 采集重叠及其用途 | 存储或发布决定 |
| --- | --- | --- |
| 股票日线 | 223 次捕获中有 12 次额外捕获。3,660 个证券日期出现在不同请求中，观察到的收盘价均一致。单日截面和单股区间有交集。 | 36,989 个证券日期各有一条日线。每行的 `close` 列和 `data.close` 都一致。公共查询读取类型化列。发布前的来源摘要覆盖 ORM 输入列，物理移除 JSON 镜像会改变摘要，需要单独核对。 |
| 复权因子 | 214 次捕获中有 11 次额外捕获。1,412 个证券日期在不同请求中有因子，其中 37 个有不同的值。37 个 Core 值都与最后捕获相符。 | 37,029 条因子涵盖全部日线日期，另有 40 个证券日期仅有因子。公共接口与工作台按相同 Core 口径读取。保留 Raw 中各次捕获的值及时间，供核对修订。 |
| 每日估值与股本 | 368 次捕获中有 11 次额外捕获。估值专项的 PE、PB 在 33,805 个非空证券日期上与 Core 均一致，并另有更长历史。市场脉搏的 50 个专项状态键在常规原件中均缺有效状态。 | 36,989 条 Core 记录与日线逐键相配。公共接口按常规 Core 库存提供字段，脉搏沿用带状态来源的校验，长期估值按原专项凭证消费。将来扩展历史时需定义合并范围、优先来源及冲突处理。 |
| 分红 | 365 次捕获中有 156 次额外捕获，54 个请求键观察到不同正文。组合专项还负责核验实施、送转和股本基准。 | 528 条 Core 记录有 528 个不同的“证券、报告期、公告日、进度”键。它们均能在组合专项中匹配，两项现金分红值及登记、除权、支付日一致。405 个键从专项补到了 Core 缺少的实施公告日、基准日或基准股本。应按事件阶段和已知日期解析后再设计公共分红接口。 |

同日异值的实例是 `000001.SZ` 在 2024-06-14 捕获到的 `125.0496` 和 `125.05`。本轮能确认当前库选中了后一次的值。要认定 37 组各自的成因，仍需供应商修订或原始精度证据。当前公共接口以已入库的因子为有效值，发布构建使用本批载入的因子序列与窗口末端基准。股票例行发布会在提升指针前复核来源摘要，历史工作台通过已发布快照读取。[快照发布与输入核对](../backend/app/stocks/update/publication.py) · [复权计算](../backend/app/stocks/marts/prices.py)

第一批选择三个按证券和交易日查询的数据集，目的是让调用方独立取得事实，也让现有工作台在进程内复用查询。分红事件、市场脉搏和长期估值的专项凭证各有具体用途。只有已有捕获能满足对应任务的字段、覆盖及时间要求，才适合共享该次采集结果。[估值凭证](../backend/app/stocks/valuation_supply.py) · [脉搏字段来源](../backend/app/market/pulse/repository.py) · [分红刷新规则](../backend/app/portfolio/routine.py)
