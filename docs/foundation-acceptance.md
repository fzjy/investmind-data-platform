## 应用怎样取数

| 独立调用方可查的主题 | InvestMind 的实际消费位置 |
| --- | --- |
| 股票未复权日线、复权因子、估值与股本 | 工作台和选股器复用领域查询计算复权图表与指标，组合使用同批股票输入。[日频合同](stock-datasets.md) |
| 证券及曾用名、日历、分类成员、财报、披露日程、公司事件、分红 | 股票指标、研究和组合使用各自的可见日期、分红与股息率规则。当前库存与有凭证的历史截止日分别查询。[股票和分红](foundation-stock.md) |
| 指数及 ETF 日线、ETF 量额与份额、主力商品日线、股票涨跌停状态 | 市场构建器对标准行情及专项证据做批量读取，按产品规则形成热力图、排行和日周月图。[市场事实](foundation-markets-macro.md) |
| 标准宏观观测、专项宏观观测 | 宏观传导、洞察和组合利率引用领域选版规则。标准观测按声明的发布时间及修订有效期，专项按已完成采集凭证判定。[宏观历史合同](foundation-markets-macro.md) |
| 可展示的新闻、公告和文章 | 新闻使用实时读取，市场可读快照或叠加实时新闻，工作台按证券和交易日组织公告。[内容合同](foundation-content.md) |

ETF 和商品新增采集会把采集时的目录指纹与原件一同保存。历史读取使用原件、成功游标及冻结作业合同。在开发库模拟目录改名、重排并缩短当前采集窗口后，仍可读出相同的 9 只 ETF 和 790 根商品日线，包括各自的原件引用。历史直写记录缺少作业和指纹时，接口只返回能够核验原游标的事实。[历史凭证规则](foundation-markets-macro.md)

公共读接口共有 **17 个**。例如 `GET /api/v1/datasets/stock-daily?symbol=600519.SH&start_date=2026-10-01&end_date=2026-10-21` 直接得到一只股票的未复权行情。产品查询仍从原有的 `/api/v1/stocks/600519.SH` 读取当前已发布工作台。领域函数在服务进程内共享，可以传递同一事务、批量证券和构建时点。[请求索引](api-requests.md) · [OpenAPI](openapi-v1.json)

事件与非股票域也能独立调用。以下两个请求分别按公告日查茅台的分红观测，按交易日查上证指数日线。

```http
GET /api/v1/datasets/stock-dividends?symbol=600519.SH&start_date=2025-01-01&end_date=2026-10-16
GET /api/v1/datasets/market-daily?asset_type=indices&asset_code=000001.SH&start_date=2026-10-01&end_date=2026-10-16
```

### 切换与回退

2026-11-19 审核通过后，本机常驻底座已在 `127.0.0.1:11383` 加载重构版。`/health` 报告数据库就绪。InvestMind1 在原代理路径上的 10 个业务响应均有数据，与切换前的正文摘要相同。常驻实例的 47 个数据集示例均通过，组合条件请求返回 304。

| 入口 | 启用与恢复方式 |
| --- | --- |
| 独立数据集 | 发布底座服务进程后由调用方按需接入新路径。回退底座应用版本会撤回新路径，已经开始调用它的项目须同步回退对应调用。 |
| 股票、市场、宏观与组合快照 | 新版本在现有发布事务中用领域查询生成产品，通过原子发布指针生效。回退时使用已验证的历史版本及其输入引用。组合条件请求仍按所选版本的 ETag 工作。[发布与恢复用例](../backend/tests/e2e/test_release_postgres.py) |
| 实时新闻、市场叠加新闻与工作台公告输入 | 实时读取随服务版本切换，快照内容随产品发布切换。恢复服务读取后可用相同证券、业务日和新闻游标对照。 |
| 采集与物理存储 | 采集继续执行已验明的复用或重取规则。这次交付无需迁移或回填。开发库备份恢复、旧版本读取和并发期间保存一致视图均有隔离 PostgreSQL 用例。[备份恢复用例](../backend/tests/e2e/test_database_backup_postgres.py) |

单域回退可只恢复该域的路由注册、共享查询及对应产品读取，再发布服务。先用该域原 URL 和已知产品版本核对，再恢复其构建作业。市场成对发布的产品和宏观同版产品须按现有发布边界一同恢复。新增只读查询及本次原件附带的目录指纹均无需逆向数据库迁移。

## 隔离回归与复跑

端到端分组 `backend/tests/e2e` 在一次性 PostgreSQL 17 中通过 163 项，用时 34 分 19 秒，隔离器登记 169 个临时数据库身份。覆盖正式发布入口、升级故障后的恢复、备份与还原、旧工作台读回及股票更新中断后的续跑。真实 HTTP 和业务数据库访问违规均为 0。

其余后端用例与新闻采集包在另一分组通过 7,605 项，用时 37 分 7 秒，真实 HTTP 和业务数据库访问违规均为 0。两组路径互斥，合计 **7,768 项通过，0 项失败，0 项跳过**，与最终整仓收集数一致。两组均有 Starlette 测试客户端使用 AnyIO 旧别名的弃用提示。

在项目根目录执行如下命令可复核。网站端口、底座端口和网站仓库按本机实例填写。

```powershell
backend/.venv/Scripts/python.exe -I scripts/verify-investmind-connection.py --backend-port 11383 --website-port 3000 --shadow-website E:/code/ai-website-cloner-danginvest
backend/.venv/Scripts/python.exe -I backend/tests/run_isolated.py --postgres pytest backend/tests packages/news-collector/tests -q --tb=short
```

要用本次验收的分组复核，可分别指定 `pytest backend/tests/e2e` 和 `pytest backend/tests packages/news-collector/tests --ignore=backend/tests/e2e`，其他隔离参数相同。
