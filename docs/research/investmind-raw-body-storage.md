# 供应商原件正文的重复存储与隔离迁移

2026-11-15 在独立底座打开只读、可重复读事务，把全部供应商捕获、批次来源和 114 行真实报价外键复制到自动销毁的 PostgreSQL 17。比较紧凑单表与分表结构，验证旧读取、同批修改、并发写入、回滚和备份。源库版本为 `20261111_0020`，未修改源库或启动采集。[实测回执](investmind-raw-body-storage.json)

## 哪些内容确实重复

| 计量 | 实际结果 |
| --- | --- |
| 捕获次数、批次与请求定义 | 4,004 次捕获。同来源、接口、请求哈希、供应商内容哈希组内有 406 次重复；119 个请求键收到多份不同哈希正文。 |
| 原始 JSON 文本 | 以 PostgreSQL 存储的 JSON 文本 UTF-8 字节核对，共 3,398 份不同正文；606 次重复，含不同请求的相同响应。没有把 JSON 键序、空白差异、JSON 数字格式归并。不同来源、接口、请求或批次仍各自保留捕获身份。 |
| 字节 | 余下副本文本约 5,503,780 字节；列级存储估算约 1,629,466 字节。实库单表含索引占 48,275,456 字节。 |

供应商原件捕获后可被现有任务补充同批请求参数及证据。生产代码中有 48 份文件直接提及该模型或该表名，分布在内容 1、数据库模型 3、采集 1、宏观 18、市场 5、组合 9、股票 11。12 份文件直接构造捕获对象，含通用 Tushare 写入、公告历史、宏观官方成员及补充、分红与基准目录。七处写入还会更新已建原件正文，分别为组合的 dividend_capture、reference_catalog，以及市场的 region、pulse、ETF、commodities、data 仓储。回读包括按 ID、批次和分类筛选的 ORM 查询、单列 JSON 投影、财务原件行号、股息和证券基准来源链。行情报价的外键目标是捕获 ID。股票卡片重建会锁定原件表；市场历史审计也直接用 SQL 读取正文。因此按请求哈希覆盖或移除多批次行会破坏现有语义。

## 隔离迁移与判定

隔离试验将正文移到以实际 JSON 字节 SHA-256 为主键的表；捕获表保留旧 ID、批次、接口名、请求哈希、供应商内容哈希、捕获时间、原唯一约束及外键目标，新建正文反查索引。原表名由兼容视图继续提供，写入触发器解析捕获与正文两部分，遇到哈希碰撞比较实际文本并拒绝合并。在已复制数据上逐行比对实际文本，迁移前、迁移后、回滚后的整行有序摘要均为 `fc12788692294187ea49faad727ec01240f3b5d1829ede80a1b2773472d27bdd`；114 条报价引用同一原件。

两个并发批次写入同一正文产生两条不同 ID 和一份正文；同批重复请求仍报唯一冲突 23505。同一捕获的后续修订不影响另一捕获。实际 SourcePayload ORM 的单列取值、添加并返回 ID/时间、正文更新、回滚均通过。

**实库维持现有原件结构。** 当前备份清单只接受指定类别的物理关系和已登记的对象保护。本次实际调用同一备份清单得到 `unsupported_database_objects`，无法用当前备份程序验证这一视图和写入触发器。另在删除两次临时捕获后留有两份无引用正文，需要单独定义回收语义。解决前对实库实施会丢失项目现有可验证备份能力。恢复点、4,004 条捕获与 119 个修订请求仍可按原路径查询。暂缓的是实库物理去重，已验证的重复次数不等于可取消的供应商调用数。

复跑入口在独立底座仓 `scripts/audit-raw-body-storage.py`，使用本仓 Python、可访问的本机只读 PostgreSQL 与一次性 Docker PostgreSQL 17。回执只输出计数和摘要，不输出原件正文。原始审计见[全库重复存储登记](investmind-storage-review.md)。
