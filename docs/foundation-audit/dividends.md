# 分红逐笔判定

以来源、接口和请求哈希聚类，按捕获时刻、Raw ID 排序。组内每种正文第一次出现以后的相同捕获计一次额外捕获。判定旧原件是否可引用时，要求它在后一个批次开始前已完成。例行任务在 HTTP 返回后可能才创建批次，故仅有时间顺序不足以认定可复用。对已复用的记录还核对了冻结游标、具体旧原件、请求身份、两份正文、批次终态与实发计数。历史池回补按作业的证券、时间窗口、分页大小和偏移重新验算请求哈希。

365 次捕获中 156 次为额外捕获。已发生且记录为零请求的复用 50 条，应重新获取 97 条，证据不足 9 条。额外捕获所属批次的请求计数共 114，包含重试。本次对实际已发请求可证明的新增节省为 0。54 个同请求异文键与额外捕获的计数单位不同。[全部捕获、批次、游标及异文时间链](dividends.json)

组合专项的 102 份原件经 HTTP 状态、字节长度与 SHA-256、业务状态、分页、字段和规范块校验，从绑定原字节按 Decimal 解出小数。比较异文、计算业务行摘要、核对 Core 与判断补充均采用这组数值。每份原件保留 Raw ID 与行号，来源标识单独记录。常规捕获中 263 份缺少 HTTP 原字节，从 PostgreSQL 已持久化的 JSON 文本按 Decimal 读取；此前采集过程中丢失的供应商精度无法还原。每次捕获的 businessRowsSource 标明证据来源。

异文按相邻两次捕获比较。解析后的业务行或字段发生变化共 5 次。解析字段与逐行业务值完全相同，差异在分页、封装或传输正文共 49 次。逐步新增、消失及取值变化的事件键见每组 comparison。日期与正文身份均保留，可据此回放相同请求在不同时间的实况。

按证券、报告期、公告日和阶段归组，528 个 Core 键可在组合专项找到，专项另有 2,500 个键。对两项现金和登记、除权、支付日逐原件变体比对，全部变体与 Core 一致的记录有 528 条，仅部分变体一致的有 0 条，全部不符的有 0 条。约定金额用十进制核对，缺失和数值零分开统计。

同一原件内有 12 个粗键对应多套字段。对在多份原件中出现的同键，比对完整变体集合，发生变化的有 0 个键。只要同键中出现过多个非空值、部分版本缺值，或有任一变体与 Core 可比字段不符，该补充字段就不计入确定值。符合确定补充口径的 Core 记录共 405 条，其中 405 条获基准股本，394 条获基准日。多腿事件、取消及其生效仍由事件合同裁决。[逐键全部变体和来源行](dividend-event-evidence.jsonl)
